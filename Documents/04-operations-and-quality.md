# 04 · 运营与质量

[文档索引](README.md) · [发行与信任](02-release-and-trust.md) · [分发与安装](03-delivery-and-installation.md) · [路线图与验收](05-roadmap-and-acceptance.md)

首轮交付 macOS 私有发行。用 FantasyKingdom 加上一到两个独立项目走完 Editor 构建、签名、公证、下载、安装、原生输入、更新与恢复。每条质量证据都绑定实际测试的 `GameRelease`、`EngineBuild`、平台目标、包摘要和验证环境。不同目标独立通过和放量。本文的自动化、告警、运营和量化目标是拟议能力。已有验证单独记录在下文。

## 1. 用发布产物验收

| 检查层 | 验收内容 | 失败动作 |
| --- | --- | --- |
| 合入测试 | Runtime 输入与焦点、Canvas 布局/命中、GameLogic ABI、资源依赖、Renderer、安装器状态机和服务契约。覆盖异常、重试、取消及进程重启。 | 阻止合入，保留最小复现。 |
| 构建门槛 | 干净工作器锁定工具链和依赖，编译声明架构。核验构建身份、包摘要、依赖闭包、发布清单、签名和平台权限。GameLogic 与目标 `EngineBuild` 的 ABI 必须对应。 | 保留构建诊断，拒绝提升该游戏与平台目标。 |
| 真实安装 | 在隔离的干净目标机用普通玩家账号从测试渠道下载，验证签名、安装并通过普通启动路径打开。验证系统安全提示、断点恢复、磁盘不足、损坏包、失败后重试与卸载。 | 该平台保持候选。记录包摘要、系统诊断和实际失败阶段。 |
| 独立 Player | 检查 GameLogic 注册、首个启用场景、实际呈现首帧。按游戏声明的设备契约测试移动、镜头、UI、中文输入等。验证失焦归还、按键释放、最小化恢复、窗口缩放及退出。 | 首帧和操作分别记结果。必需用例失败即冻结该目标。 |
| 更新与恢复 | 从已发布版本升级，演练下载中断、验证错误、安装中重启、启动失败，以及保留可用安装、回滚渠道和存档处理。检查新旧路径对已安装用户的影响。 | 维持最后已知可用渠道，用演练结果修正恢复脚本。 |
| 私有灰度 | 内部、合作开发者及玩家各用真实交付入口。按游戏、目标、OS 和渠道看安装、首帧、首次交互及错误，保留对应健康探针。 | 暂停扩大范围。用目标级操作控制影响面。 |

一次报告应保存 `EngineBuild`、`GameRelease`、发布渠道及其代次、包哈希、安装前后版本、OS 与架构、图形后端、实际输入方法、失败步骤和原始诊断的脱敏引用。测试结果区分模拟、原生事件注入、物理设备和真实用户样本。永久验收记录可以保留摘要和清单，原始日志按期限清理。

### macOS 的输入回归怎样验收

历史缺陷的现象是 Player 正常出画，按键和光标 API 却失效。旧代码为同一 Cocoa 视图创建第二个 SDL 窗口，焦点和事件到达了渲染包装窗口，Player 过滤掉了另一个窗口 ID。提交 `18f6d70` 让 Runtime 渲染借用 Player 已有的 SDL 窗口。旧包和修复包对照验证到窗口焦点、W 键和隐藏光标请求由失败转为成功。新包已通过原生 macOS 键盘事件验证 W 移动和松开，SDL 事件回放验证右键转镜，光标隐藏与恢复、文本输入启动、区域和停止通过。该包从 FantasyKingdom Editor 构建耗时 10.823 秒，`codesign --verify --strict` 通过，注册了 2 个 Script、3 个 Module，打开 `Demo_01` 并呈现 2560×1440 首帧。该数据对应一次本机构建及 ad hoc 签名验证。生产签名、公证、干净设备安装、实体手柄和触控笔继续作为独立门槛。 [Player 启动和窗口](../GameSprout/GameSproutPlayer/PlayerMain.cpp) · [Runtime 输入实现](../GameSprout/GameSproutRuntime/RuntimeInput.cpp)

首轮建议把这一故障做成两层测试，并统一记录输入来源。

1. 平台探针用最小 Player 保留旧路径和修复后的可观测差异，断言实际获得输入焦点的 SDL 窗口 ID 与 Player 处理的窗口 ID 一致。按下 W 和松开 W 要改变 Runtime 的状态，光标隐藏与恢复要改变系统状态。
2. 真实游戏测试从已签名发行包启动，用 macOS 原生键鼠事件按下并松开 W，检查角色先走再停、Walk 与 Idle 正确切换。测试右键按住并转镜、失焦后松键、焦点恢复、再次移动、左键按下后同帧拖出摇杆底盘。至少一个独立项目依照其自己的控制方式补充交互断言。
3. 发布报告分别标明操作系统输入、SDL 回放和 Runtime 注入。回放可覆盖同帧顺序、取消和双指捕获，适合高频回归。真实设备资格以实际输入设备执行为准。

提交 `145f243` 的 FantasyKingdom Editor Game 窗口已在 716×371 逻辑像素和 1432×742 渲染像素下验证同帧按下并拖出底盘，满推实测 1.99 m/s，配置速度 2 m/s。双触点由测试注入，同时走路和转镜、松开回 Idle、Stop 恢复编辑场景均通过。还补测了非零视口原点与竖屏安全区。此证据归属 Editor 与 Runtime 回归。 [输入 API 约定](../GameSprout/Docs/RuntimeInput.md) · [Runtime 输入测试](../GameSprout/GameSproutRuntime/Tests/RuntimeInputChecks.cpp)

### 兼容性证据和上线范围

每个受支持的组合至少记录 OS 版本、CPU 架构、图形后端与驱动代际、签名/安装途径、存档位置和所需设备。维护最低版本与主要现行版本，按风险增加 Retina/普通 DPI、单屏/跨屏、窗口/全屏、原生键鼠/游戏声明的手柄或触控。每个组合分别标注仅构建、模拟器、真机安装、首帧、原生交互和恢复是否通过。样本量和失败数跟随每个组合记录。

| 目标 | 已有验证边界 | 进入对应渠道前 |
| --- | --- | --- |
| macOS Player 和 Launcher | 范例项目在已有 macOS 环境启动和输入验证，Metal 后端。 | 首轮覆盖声明支持的架构和 OS 版本，完成可信签名、公证、干净机真实安装、原生输入和升级回退。 |
| iOS | 真机架构产物检查，模拟器无窗口加载 GameLogic 和场景。模拟器的图形路径受 SDL_GPU 的 Metal 能力要求阻挡。 | 按所选渠道完成签名及装机，验证真机首帧、触摸和安全区、切前后台及升级。 |
| Android | APK 验证过 v2/v3 签名、16 KiB 对齐和入口。 | 在覆盖 Vulkan 与目标 ABI 的真机上装机，验证触摸、缩放与安全区、恢复和高低端设备表现。 |
| 鸿蒙 | 构建过未签名 HAP，核验资源清单、ELF 入口。 | 以支持的 SDK 和设备版本实测签名包、Vulkan 后端、真实输入及安全区。 |
| Linux Player | Linux ARM64 虚拟机打开场景并呈现首帧。 | 实测硬件 Vulkan、目标发行版、图形会话和目标架构，验证安装依赖与输入。 |
| macOS Server、Linux Server | 曾以无窗口方式打开测试场景。 | 独立验证部署、健康检查、重启恢复、协议兼容、负载与服务存档。 |

以上历史记录参照提交 `a765437`、`18f6d70` 和 `145f243`。后续新增平台按发布渠道及该游戏的平台状态独立开启。已通过的构建或平台资格会在引擎、签名链、安装逻辑或关键驱动变化后重新评估。 [平台职责及图形后端](01-platform-architecture.md)

## 2. 观察系统和可复现报告

统一关联构建作业、发布尝试、安装尝试、启动会话和玩家同意提交的工单。公共维度包括游戏、平台、系统主版本、架构、渠道代次、`EngineBuild` 和 `GameRelease`。版本和游戏维度在日志可查，高基数标识进事件仓或抽样日志。高频指标用有限标签汇总，按区域、客户端版本、失败码拆分，防止告警与查询成本失控。

| 链路 | 观察信号 | 看到异常时先切什么维度 |
| --- | --- | --- |
| Editor 和构建 | 提交到接单时间、重跑频率、依赖扫描/编译/签名/公证分段时长、Worker 失败、待审积压、失败码。 | 游戏、引擎 SDK、目标架构、工具链版本、共享或专用队列。 |
| 发行和鉴权 | 目标状态转换、审批和撤销延时、渠道代次、版本查询、异常身份和操作审计、下载授权失败。 | 单个租户或目标、区域、权限配置、新旧 Launcher、撤销传播进度。 |
| 下载和安装 | 发放/认领/结算、传输与回源字节、重试、断点恢复、签名/摘要失败、磁盘、激活或回滚结果。 | 渠道、版本、区域、大小档、网络类型以及新装、更新和修复。 |
| Player | 进程启动、GameLogic 注册、场景加载、首帧、原生输入探针、崩溃/挂起、GPU 启动失败、存档读写与迁移失败。 | 系统、设备族、架构、输入类型、图形后端以及具体阶段。 |
| 运营 | 扫描和审核队列、恶意包确认、申诉时长、恢复演练结果、支持争议、预算消耗速度、错误率与告警覆盖。 | 发布方、游戏、地区、严重度、证据存续情况。 |

玩家侧产品分析、诊断附件、服务运营日志各定义用途、访问权限、保留期与删除方式。诊断面板先让用户预览和选择附带项，默认采用分组设备信息和短期随机 ID。输入仅记录测试探针结果、设备类型和事件计数等必要信息，过滤原始按键、输入法正文、文件路径、账号、令牌和存档。崩溃转储和涉及用户资料的样本走单独授权、访问审计和到期删除。日志入库前清理身份与凭证，误入生产日志时按数据事件处理。分析拒绝或客户端离线需要单独计数，汇总时披露覆盖范围。试点可非强制地邀请玩家提供支持诊断。保留期限、删除与导出要求在扩大地区前由负责人确认并写入决策记录。

**Editor 工单复现包** 由 Launcher 生成事件关联码，用户确认后再附加诊断摘要。开发者用关联码查到确切的目标构建和已发布版本。工单字段至少有步骤、预期和实际结果、系统/架构/图形后端、输入类型、引擎与游戏摘要、错误阶段和脱敏日志；可选附可公开的最小场景或脚本。平台提供同版本隔离重跑，固定场景、测试输入序列和设备档位，记录首帧及操作结果。私有原始工程和符号保存在授权范围内，支持角色通过受控工具获取需要的工单字段。验证修复时把复现脚本加入对应目标的门槛，再用相同证据链跑候选包。

## 3. 成本与资源边界

发布者、游戏和平台目标分摊可归属的用量，服务团队负责全局预算。每项支出标出实时可控上限、费率估算和账单对账途径。用正常日、首发峰值日和异常流量三组估算预算，保留安装修复和事故恢复所需的独立额度。供应商账单与分发日志的延迟要计入预留。

| 成本或风险面 | 计量单位 | 限制及降级 |
| --- | --- | --- |
| 编译、目标签名、公证和构建池 | CPU/GPU 分钟、并发 Worker、队列长度、签名/公证尝试 | 发布者和全局并发分池，作业超时与取消。命中同输入的可验证产物，避免重复提交昂贵任务。热门游戏用自己的额度。 |
| 上传、隔离、扫描和对象存储 | 上传字节、对象数量、扫描/解包时间、GB 月、备份与复制字节 | 限包体和解压展开尺寸，隔离上传，未完成对象定期回收。受支持发行、回滚及事故证据按保留策略存放，清理前检查引用。 |
| CDN、出口与回源 | 实际和在途字节、去重后的尝试数、请求、回源和边缘执行 | 按会话/发布者/游戏/区域/全局发放，用已结算加未结算预留控制配额。授权、流量和费用分别追踪。CDN 是其中一个交付设施。 [下载预算和授权](03-delivery-and-installation.md) |
| API、目录、账号、数据库和队列 | 请求、查询耗时、热键、并发、连接及队列深度 | 接入层和租户层限载，优先保障版本查询、授权恢复和后台停发。低优先级任务退避或延后，避免故障时重试放大。 |
| 监控、日志、崩溃符号和工单附件 | 每日事件、GB 写入/查询、符号和转储体积、工单页数 | 入口分配体积及事件预算，可抽样一般成功事件。撤销、安全事故和财务审计走单独限定的容量。 |
| 人工审核、用户支持和可选商业化 | 人工分钟、申诉量、每笔交易的费用/退款和对账工作量 | 按审核风险分级，暂停异常发布者的新增任务。未来支付和纠纷预算单列，由对应团队处理。 |

拟议预算传递顺序为警告、单租户或区域限流、暂停低可信新流量、暂停受影响目标发布。修复或断点续传可用预留额度。验证各入口都遵守额度，包含镜像、临时凭证、回退区域及缓存命中路径。测试中记录允许、预留、结算、拒绝和恢复的账本变化，按实际业务归属对账。费用预测同时记录可转嫁的发布者额度、团队承担的固定费用和事故冗余。准入容量依据试点实测与运行预算确定。

## 4. 事故响应、备份和存档

值班收到告警后确认影响的游戏、平台、区域、已安装用户与新安装用户。指定一名事故负责人，记录时间、操作人、渠道代次和决定。发行、基础设施、安全、支持各有值班或备用联系人。生产停发、撤销、恢复或账本限额调整均产生审计记录。恢复前让受影响目标经过重新验证和小范围放量，再根据相同指标逐步扩大。

| 事故 | 先止损 | 怎样恢复并确认 |
| --- | --- | --- |
| 一次坏发行 | 停止受影响游戏与平台的自动更新和灰度，冻结该渠道的提升。标记候选包的启动或安装错误，保留失败证据和已知可用版本。 | 将相关渠道指回兼容的已验证版本。确认已安装玩家的启动路径、未完成安装和回滚是否可恢复。发布热修复并补用例。 |
| 广泛控制平面或交付故障 | 冻结发布写入，限制重试，维持可用的离线路径和已验证安装。按鉴权、目录、存储、边缘和 Launcher 启动分层探测。 | 经演练的故障转移逐步启用，恢复脚本校验数据库与渠道代次，避免旧指针重新生效。探针和外部玩家样本均恢复后放量。 |
| 签名私钥或发布凭证泄露 | 隔离密钥和对应工作器，停止签发，冻结受影响信任域内的提升，保全审计并判定影响时间与摘要。 | 推送受信根授权的撤销和换钥，禁止受影响的构建继续安装。使用干净工作器、确认可信来源重建并重签。审计过渡期 Launcher 对新根、撤销和离线缓存的处理。 |
| 可疑或有害包 | 隔离摘要和发布者的关联作业，禁止新授权，按范围下架、吊销或封禁。保留原始证据及法律/运营要求的访问记录。 | 核验别名、渠道、缓存和镜像都执行撤销。向受影响玩家提供清晰状态、升级或移除路径。采用干净包重新审核和恢复，处理发布者申诉。 |
| 配额耗尽、突发流量或滥用 | 在租户/目标/区域缩小领取和并发，保留修复额度，停止低可信会话。控制在途预留，逐层确认成本边界。 | 修复限载条件并验证账本与账单差异。分批恢复流量，检查正常玩家误限和重试成功。预算调整由责任人审批。 |
| 存档读取或迁移损坏 | 停止自动迁移与相关版本扩量，为受影响用户保留旧存档及当前副本，隔离出问题的版本组合。 | 用与游戏约定的兼容路径或修复程序恢复，通过旧存档、失败重试、空间不足、跨版本回退测试。软件回滚前单独核对存档能否读取。 |
| 元数据或对象数据丢失 | 停止生产写入和发布，把备份恢复在隔离环境。保留现有撤销、审计和新代次证据。 | 从备份与独立审计重放有效数据，按摘要检查对象可读及签名有效。验证恢复时的权限、撤销及渠道指向后再恢复写入。 |

备份范围包括发布和渠道元数据、操作审计、权限、发行清单、对象索引与需要保留的发行包。信任根和签名密钥按独立密钥恢复方案管理，验明何人可恢复及何时必须换钥。预算账本恢复要保留仍可到达服务器的在途下载和授权；恢复卷不能凭旧记录重新发放重复额度。试点做一次从空环境恢复并记录实测数据损失窗口、恢复时长和人工步骤。公开前按数据类型定义可容忍数据丢失量和恢复时间，并按这些边界完成演练。

存档按游戏和用户独立于安装目录存放，更新或卸载时按明确的用户选择处理。游戏声明存档版本、迁移兼容范围、可回退条件和恢复步骤。不可逆迁移在确认备份可读后才执行；回滚时优先保护新旧存档副本，依据版本兼容规则锁定能启动的包。云存档如后续建设，单独处理冲突、离线写入、删除、恢复和数据保留。服务端恢复能力与单机本地存档语义分开测试。 [安装、回滚和离线](03-delivery-and-installation.md)

## 5. 审核、发布方滥用与玩家支持

私有发布接入已知团队和受邀玩家。作者只能管理授权的游戏和目标；构建提交、审批、生产发布、紧急撤销和密钥操作各有权限，关键操作做复核或二次确认。上传隔离后扫描恶意文件、危险解包内容及异常权限，再进入审核。内容公开前增加游戏元信息、素材授权、用户举报、违规处置和申诉的入口。待审核、受限和已公开条目各使用独立状态，支持按目标、地区和严重度处理。

滥用可能来自刷下载、凭证外泄、自动造号、诱导安装、反复提交恶意变体和资源透支。通过风险分级、上传和构建配额、重复摘要关联、异常账号访问审计、定向停发和人工复核处置。安全扫描发现的误报需有带证据的人工复核和恢复路径。给玩家的状态要能解释安装失败、版本撤回、升级是否必要，以及如何找回已有安装或存档。支持后台默认显示工单所需的有限信息，升级访问走审批及审计。

商业化可在安全发行和可恢复运营稳定后独立决策。先验证发行、合作方权限与玩家登录或邀请。需要付费时，先把权益从支付拆开，可用邀请、赠送或测试权益验证授予、撤销、换设备与离线容错。支付阶段再定义定价、订单、异步确认、幂等重放、退款、争议、账务对账和支持责任。付款、发放权益、记账和下载授权使用明确的状态，重复回调不能重复授予，支付异常也不应破坏已经确认的合法离线使用策略。公开销售范围、商店规则和结算要求在另一个决策中核定。

## 6. 如何量化技术优势

试点验证从 Editor 到真实 Player、从故障回到 Editor 复现的闭环。通用交付服务可以缩短基础设施实施，版本归因、资源差异、目标平台资格、原生输入自动化和可恢复发行由平台持续积累。对同一组游戏和目标，以手动打包与分发流程为基线。固定项目版本、网络条件和硬件档位，记录有效操作时间、等待时间、失败原因与重复劳动。先测 FantasyKingdom，再用一到两个独立开发团队的实际项目检验适用性。

| 指标 | 分子与分母 | 使用方式 |
| --- | --- | --- |
| 首装成功率 | 激活一个经验证安装的唯一首装尝试 ÷ 已取得授权并开始的唯一首装尝试。 | 按游戏、平台、区域和网络分层。尝试窗口固定，记录取消、超时及终态未知。多个自动重试合并到同一尝试。 |
| 有效启动率 | 产生规定的就绪信号的唯一启动会话 ÷ 所有已尝试启动的唯一会话。 | 图形版用首帧就绪，Server 用场景与服务就绪。交互探针单列，首帧后输入仍可能失败。 |
| 原生交互验证 | 通过的必需原生用例 ÷ 该包对应设备组合的全部必需用例。 | 发布门槛按组合判断。缺测保留独立状态，模拟和注入结果旁列。 |
| 更新与恢复 | 原版本仍可用或新版本按计划激活的唯一更新尝试 ÷ 所有已开始的唯一更新尝试。事故演练另记回滚通过数 ÷ 演练次数。 | 正常更新成功和回到可用旧版分别计数，追踪存档恢复。昂贵的一次回滚即纳入调查。 |
| 构建与发布效率 | 统计每个进入终态发布请求的提交到可安装用时、作者主动操作用时、排队和审核时长。 | 成功样本报分位数，同时报告失败/取消/未完成占全部请求的比例。与手动基线对照。 |
| 设备故障复现闭环 | 有足够信息在相同版本/设备档位复现的可行动工单 ÷ 所有进入分诊的同类可行动工单。 | 记录缺少证据的原因和复现时长。修复后能进回归用例的工单另计。 |
| 单次有效交付成本 | 一段期间内归属的构建、传输、存储、日志和支持费用 ÷ 期间确认的成功安装或成功有效更新数。 | 新装、更新分开报告，实际成本与近实时预测分开。并报流量放大率，实际传输字节 ÷ 有效交付所需的缺失字节。 |
| 开发者复用率 | 完成第二次有效发布的试点团队 ÷ 完成第一次发布且进入完整观察期的试点团队。 | 结合访谈区分自然发布周期、质量、用时和流程障碍。样本小的时候展示人数与原始计数。 |

试点看板同时给出分母、观测窗口、环境和缺测比例。安装与启动指标在终态缺失时保留未知桶，公开分享时说明授权范围和报告覆盖。没有可靠采样的组合继续补测。报告分位数时写明样本量和数据源，避免把少量实验样本写成服务承诺。

**扩大范围的门槛** 建议每个试点游戏用完整包各跑一次干净安装、更新与中断恢复，并在必需兼容组合上按兼容矩阵执行首帧及原生交互。至少一次渠道回滚、一次存档保护演练、一次从备份恢复和一次预算过载演练要留下可复查记录。已知阻断级问题会卡住相应目标提升。试点结束后将成功率、时长、错误预算、成本上界与异常容量按真实基线冻结到路线图和决策记录。后续公开渠道批准时同时检查兼容性、审核能力、支持响应和运营支出。 [路线图与验收](05-roadmap-and-acceptance.md) · [决策记录](DECISIONS.md)
