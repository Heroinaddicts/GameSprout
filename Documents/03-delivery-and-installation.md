# 03 · 分发、安装与成本控制

[文档索引](README.md) · [平台架构](01-platform-architecture.md) · [发布与信任](02-release-and-trust.md) · [运营与质量](04-operations-and-quality.md)

本文定义 GameSprout Game Launch Platform 的玩家端 Launcher 如何选择、下载、验证、安装和启动一个已发布版本，并控制下载的字节、请求与成本。服务、状态机和预算规则均是拟议设计。现有 Editor 已能构建独立 Player，Player 能读取 `Player.json`、加载 GameLogic 并打开首个启用场景。现有产物没有 Launcher 分发所需的签名发布清单、全球字节账本或安装回滚策略。 [构建实现](../GameSprout/Module/BuildSetting/PlayerBuildJob.cpp) · [Player 资源清单](../GameSprout/GameSproutPlayer/PlayerPackage.cpp) · [Player 启动](../GameSprout/GameSproutPlayer/PlayerMain.cpp)

## 1. 交付单位和目标平台

| 用途 | 建议交付方式 | 关键条件 |
| --- | --- | --- |
| 桌面首批试点 | 每款游戏交付已签名的完整独立 Player，携带其兼容的 Runtime、GameLogic 和资源。Launcher 安装并以独立进程启动。 | 优先验证现有 macOS 导出。Windows 按新增导出目标验收，Linux 选择实际支持的发行版和 CPU 架构。签名、验签和安装使用目标平台的方式。 |
| 桌面共享引擎优化 | 在固定的平台、架构、引擎构建和 SDK ABI 下复用不可变引擎包。游戏占独立进程，启动时绑定确切引擎摘要。 | 先测量下载及磁盘收益，再验证签名、动态库加载、引擎并存、崩溃恢复和回滚。完整 Player 是试点交付基线。 |
| iOS、Google Play Android、鸿蒙 | 初期由 Launcher 显示目录和适用的已获准渠道，安装、签名及更新交由该渠道。 | 以目标商店及地区的审核和分发规则为准。iOS、Android 上的 App 内游戏目录如果后续采用网页或串流等模式，需要按所选模式独立验证。当前的桌面原生 GameLogic 分发模型不作为移动商店的交付前提。 |

Apple 审核指南第 2.5.2 条约束下载并执行改变 App 功能的代码，第 4.7 条规定特定应用内软件类别和附加要求。Google Play 对从 Google Play 以外来源下载 `.so`、DEX 或 JAR 等可执行代码设有限制。平台资格、签名和渠道要求在每次发布前按正式规则核实。 [Apple 审核指南](https://developer.apple.com/app-store/review/guidelines/) · [Google Play 设备与网络滥用政策](https://support.google.com/googleplay/android-developer/answer/16559646)

## 2. 私有产物、清单和缓存

由发布服务将审核通过的构建从隔离区提升到只读分发空间。上传凭证限对应租户、构建和对象前缀。分发空间禁止公开读取。CDN 仅通过服务身份读取已发布对象，客户端只对受保护的 CDN 入口发起请求。生产和测试凭证、存储及预算各自独立。平台可以配置源站访问控制，例如在 S3 存储桶策略中仅授予指定 CloudFront 分发 `GetObject`。 [CloudFront S3 源站访问控制](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html) · [发布与信任](02-release-and-trust.md)

| 对象 | 建议字段与行为 |
| --- | --- |
| 渠道记录 | 游戏、频道、平台、地区、发布序列、选中的发布摘要。更新服务原子切换频道指向，并保留记录。回滚通过更高发布序列重新指向旧的可信版本，客户端仍能防止旧频道声明重放。 |
| 签名发布清单 | 清单格式版本、游戏 ID、发布 ID、玩家可见版本、目标 OS/架构、平台最低要求、启动入口、原生签名信息、包大小及摘要。采用固定规范编码，签名覆盖所有影响下载、安装或执行的数据。密钥 ID、签名算法和撤回规则见发布文档。 |
| 运行兼容信息 | 发行记录中的 `engineBuildId`、引擎构建清单摘要、SDK/工具链与 ABI 标识、必需的 GPU 后端和相关资源格式版本。磁盘安装以内容摘要定位。游戏的版本号用于展示，兼容性按具体构建合约检查。 |
| 分块描述 | 内容摘要、传输编码及该表示的确切字节长度，及其在包中的文件位置或重建规则。可附明确的基础版本摘要及签名补丁描述。服务从可信清单查找大小和长度，客户端无法自报额度。 |

完整 Player 是最初的交付和恢复单位。客户端可以并行下载完整包的有界分块。分块按传输表示的摘要命名，请求身份与授权在命中 CDN 缓存前检查，通过后使用摘要和必要编码维度作为缓存键。CDN 保持已选的二进制传输表示和内容长度，防止自动编码转换改变计量。用户令牌与随机参数不会产生单用户对象缓存。对合作方私有构建、未上市游戏和灰度版本，按租户、频道和访问范围控制查询及读取。公共版本之间可复用等同的不可变内容。 [CloudFront 缓存策略](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cache-key-understand-cache-policy.html)

本地只缓存已经完成摘要验证的分块。游戏安装、运行中的进程、暂存事务和最近可回退版本持有引用。失败事务清理时先释放自己的引用，垃圾回收在无引用后回收对应对象。缓存可重建，索引丢失时以签名清单和磁盘验证结果恢复。GPU 管线缓存可按设备、驱动、引擎及着色器构建区分，驱动更新后允许重建。

差分是后续优化。与现有已验证基础版本匹配才能应用补丁。解压或重建在暂存目录完成，验证目标包的完整摘要以及目标平台的原生签名，再进行安装。基础版本、空间或重建验证不满足时，可退回完整包，使用新的下载授权和额度。对有签名封印的应用包，补丁重建出正式签名所对应的原始字节。分块大小、压缩和并发由下载吞吐、重试成本、请求费用和本地解压峰值共同决定，通过实际样本选择。

## 3. 下载授权和字节账本

### 一次下载如何获得额度

1. Launcher 通过发行服务的 `ResolveLaunchPlan` 获取已匹配的发布计划，再根据登录或访客策略取得下载会话。分发服务检查游戏、发布渠道、地区和权益，再返回允许版本的签名清单。授权包含会话、允许的版本、期限及所适用的预算，领取会话本身也限速和限并发。
2. 下载计划只申请本地缺失或损坏的分块。服务从发布清单查找每块的最大可传输字节数 `b`。原子检查当前窗口的已结算量 `S` 与未结算预留 `R`，只有全部适用预算均满足 `S + R + b ≤ L` 才发放尝试凭证。`L` 是各预算上限，同一笔传输在账号、游戏、发布者、地区和全局维度分别占用额度，财务汇总按下载尝试 ID 去重。
3. 每个尝试绑定随机 ID、会话/主体、发布与分块摘要、允许长度、方法、分发区域和期限。边缘在开始返回响应前校验授权并原子认领尝试，缓存命中也执行认领。只允许有效凭证在其认领域开始一次传输，服务限制输出最多为已预留字节。
4. 边缘关闭传输后，以可信实际发送字节和幂等的结算记录将预留转为已结算。有效发送量无法确认时保守扣除完整预留。如果能够证明凭证从未使用且已无可使用路径，才可返还未用额度。已经开始的传输只在结束得到确认后释放未使用部分。客户端的完成声明用于进度及体验指标，结算采用服务侧记录。

授权凭证泄露时，短有效期限制使用窗口，精确分块和原子认领限制重复使用。普通 CDN 签名 URL 本身可在有效期内多次使用。CloudFront 按 HTTP 请求时间校验失效，已开始的响应可能继续送完。在需要硬预算的下载路由，应验证选定 CDN 或下载网关具备缓存命中前的认领能力。无法执行一次性认领时，将二进制流量转到具备该能力的入口，或者明确将签名 URL 方案定位为软预算。 [CloudFront 签名 URL 到期语义](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-signed-urls.html)

### 并发、重试和区域额度

- 同一个申请的重发使用相同幂等键，收到同一尝试凭证。令牌认领后已经具有发送字节的可能性。下载中断后，新的真正传输使用新的尝试与预留。相同分块的多个客户端连接不能同时认领同一尝试。
- 以整块为默认恢复单位。客户端保存已校验的分块及其状态，恢复会话时申请剩余块。开放字节范围时，仅接受策略限定内的单区间，按实际允许范围预留，并拒绝会被代理解释为整对象下载的请求。CloudFront 对某些无效 Range 会返回完整对象，部分缓存未命中还可能向源站请求更大范围。整块对象能简化出站字节和源站读取的上界。 [CloudFront Range GET 行为](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/RangeGETs.html)
- 试点可以用单一事务账本管理硬预算。区域化后，全局先给每个区域分配有限租约，各区域子额度总和受全局及相应发布者、游戏或高风险账号的总额度约束。需要跨区域共享的单一账号额度由同一认领归属管理，或在对应区域发放不重叠的子额度。预算认领和结算带租约编号及代际，防止网络恢复后过期节点继续发送。租期届满仅关闭新认领，仍未结算的已开始传输计入上级预算。
- 区域断联先消费已有额度，耗尽后拒绝新的二进制传输。切换 CDN、区域或发放新租约前，扣住旧路径可能继续发送的额度，双方使用同一有效全局预算。多条下行线路可提高可用性，权威额度和旧会话存活期限决定最坏超额上界。
- 明确区分授权发生窗口和供应商计费窗口。账本状态保留记录所属时段和剩余在途上界。对要求按自然日或自然月封顶的预算，在换期时为可能跨期发送的未结算传输预留新窗口额度，或在期界前停发会跨期的长尝试。换期和重新部署不会自动释放额度。

### 公平访问和额度耗尽

预算按账号/会话、设备风险、发布者/游戏、地区和全局分层，结合请求速率、同时活跃下载数、在途字节，以及日/月字节额度。一款热门游戏的配额耗尽时优先收紧该游戏，防止拖累其他游戏。可给新玩家、低速网络上的正常重试、已有安装的修复更新保留有限额度。测试、CI 和合作方使用独立服务身份及预算，按职责授权和撤销。

共享网络、代理、漫游及 IP 变化使用风险和速率信号。正常玩家以会话和账号保持进度。高风险的授权申请可以增加验证，普通分块下载支持稳定续传。下载接口区分授权失效、额度耗尽和服务暂不可用。遇到限额时，Launcher 使用 `429` 及可用的 `Retry-After` 判断下一次重试时间，退避加入随机间隔，并保留已验证的分块。配置应能分别暂停访客新下载、异常账号、单个发布者、地区或版本，保留目录访问和平台允许条件下已安装的离线游戏。

### 用量观测与熔断

- WAF 和 CDN 负责网络层防护、请求频控、签名校验和缓存。应用账本负责硬字节限额。在支持分地域计数的 WAF 中，全球分散流量可能各自低于地区阈值。供应商报告的计数范围和过载行为应在采购与压测时确认。 [Cloudflare 计数范围](https://developers.cloudflare.com/waf/rate-limiting-rules/request-rate/) · [Cloudflare 限流故障行为](https://developers.cloudflare.com/waf/rate-limiting-rules/troubleshooting/)
- 按固定时间窗观测凭证颁发、认领冲突、拒绝、结算字节、在途预留、命中率、异常 Range、用户恢复成功率以及地区和发布者贡献。在线估算同时计入 CDN 请求、下行和回源、存储、边缘执行及日志。服务只能硬限制它完整控制的请求和字节路径，金额预警还应按保守地区单价预留费用。账单数据有延迟，用于核对和调参。 [CloudFront 实时日志](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/real-time-logs.html) · [AWS 预算刷新频率](https://docs.aws.amazon.com/cost-management/latest/userguide/bcm-lite-use-budget.html)
- 根据已结算量与预留总量调整签发速率，触发时逐级限并发、关闭低可信新会话、暂停特定对象或区域分发。测试和内部账号下载与公众下载各占独立的额度池。按平台、地区和网络类型观察误限率，恢复时逐步放量。必要时使用固定费率方案作为费用兜底，并在合同中确认包含的服务、使用额度、持续超额对性能的影响和账外费用。 [CloudFront 固定费率计划](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/flat-rate-pricing-plan.html) · [运营与质量](04-operations-and-quality.md)

## 4. 安装、启动和回滚事务

一次安装只将完整且经过验证的版本设为可启动。客户端记录持久化状态，下载会话可以续接。重试以事务 ID 和目标发布摘要为键，按落盘结果恢复。

| 阶段 | 写入和验证 | 失败后行为 |
| --- | --- | --- |
| 解析发布 | 获取当前允许的签名清单，确认平台、架构、引擎、撤回和签名状态。核算下载、解压/差分临时空间、新旧版本并存及预留空间。 | 当前可启动版本继续可用。无法更新的原因可重试或反馈。 |
| 下载与固化 | 下载到临时文件，验证长度和摘要，再登记为完成的不可变分块。保留待安装对象引用。 | 断网或退出后保留已验证块，从缺失处继续。磁盘不足时提示空间需求，按引用回收无用缓存。 |
| 暂存与验证 | 在目标磁盘暂存。验证目标包摘要、原生签名、文件路径、启动入口和明确的依赖。解包限制路径和展开大小，平台合法链接仅允许指向同一版本内的已验证对象。 | 删除或隔离未完成产物，继续保留上一个可用版本、运行中的版本和任何存档。 |
| 提交与启动 | 完成版本目录写入后，通过同卷原子发布及持久化安装索引更新当前版本指针。每个游戏只允许一个提交者，运行的进程保持其版本引用，新进程读取已提交版本。 | 恢复过程按持久化记录和已验证的版本目录判定提交结果。若提交完成但 Launcher 中断，重新打开后该版本仍可启动。 |
| 回滚与清理 | 当前版本失败时显式回到上一个仍许可且可启动的游戏与引擎组合。日志、签名、渠道和安装状态保留用于诊断。 | 签名失效、撤回、存档版本不兼容或在线权益不满足时，提供明确原因及修复路径。回收在无进程与事务引用后执行。 |

Launcher 将经过验证的文件交给独立 Player 或目标 OS 启动器，传入明确版本路径及所需的最小配置。游戏崩溃有独立退出状态，下载状态和安装指针继续由 Launcher 管理。共享 EngineBundle 时，完整游戏版本和确切引擎版本一起切换。单进程隔离崩溃，文件、网络及系统访问边界按发布者信任和操作系统策略执行。 [发布与信任](02-release-and-trust.md)

存档、配置、截图和用户生成内容放在游戏 ID 与用户范围下的独立可写目录，更新、卸载和回滚通过安装索引处理可执行产物。存档迁移有独立格式版本和备份。回滚程序前确认旧版能读取相应存档，已有较新存档保留可恢复副本。运行与更新允许并行，不覆盖仍在使用的可执行文件和资源。已安装游戏在离线时按发行方的离线权益及撤回策略启动，未完成更新显示可恢复状态。

## 5. 验收和决策

下列是验收场景与可观察结果。数值阈值由试点采样后确定，写入路线图和决策记录。

| 场景 | 预期证据 |
| --- | --- |
| 同一下载尝试在多个边缘节点并发认领，请求命中缓存 | 最多一个连接发送包体，预算账本无重复放行。同步竞态、回放与授权失败有可区分的记录。 |
| 第一次传输成功但客户端丢失确认，随后继续请求同一块 | 客户端回执不释放额度。实际重试使用新的预留。账本、日志和 CDN 用量能按尝试 ID 对齐。 |
| 下载中途断网、切换 CDN 或地区，旧连接延迟报告 | 已校验块不重传，过期租约不再认领，旧在途字节仍受预留约束，全局区域累加不超授权总额。 |
| 未授权访问源站、错误签名、越界或不受支持的 Range | 无可执行文件或整包发送。拒绝路径开销有上界，缓存命中无授权降级。 |
| 共享出口下多个玩家下载，另有脚本攻击会话 | 风险会话被限制，正常玩家在保留额度内继续，按地区、网络和玩家群组核查误限流。 |
| 坏分块、坏补丁、磁盘不足或下载/提交任意阶段崩溃 | 恢复后仍能启动旧版或完整提交的新版本，没有半安装的可启动入口，空间回收有迹可查。 |
| 游戏运行中更新并回滚，同一版本绑定了不同 EngineBundle | 正在运行的文件和存档保持有效。新进程只读取已提交的兼容组合，不匹配的引擎在加载 GameLogic 前被拒绝。 |
| 多游戏独立 Player 与可选共享 EngineBundle 做 A/B | 对比首装、更新和仅修复的下载字节，磁盘峰值、p50/p95 首次可玩时间、成功安装率和回滚成功率。达到预定收益并通过签名、兼容和恢复测试后扩展共享方式。 |

试点优先确认完整 Player 的包体和签名、基本下载预算及安装恢复。对固定分块、CDN 边缘认领、全局账本与区域租约，逐步测量在途开销、故障恢复、正常玩家完成率和每次成功安装的成本。公开发布前冻结可接受的费用上界，验证授权、限额及隔离策略覆盖所有公开二进制入口。 [路线图与验收](05-roadmap-and-acceptance.md) · [工作区和交接](06-workspace-and-handoff.md) · [决策记录](DECISIONS.md)
