# 05 · 路线图与验收

## 当前接力任务

**下一件事是把现有 macOS Player 变成一份可由外部安装工具校验并运行的发行版本。**

从原 FantasyKingdom 工程导出两个可重复的候选版本，记录官方引擎构建、游戏发布目标、GameLogic 与整包摘要。在独立安装位置验证两个版本的安装、启动、失败恢复和存档。先验证能否从 Git 和已授权的外部依赖恢复开发环境，再实现本地最小发行流程，确认 Player 清单、系统代码签名、发行清单和安装记录的边界。

## 阶段 0 · 本地端到端样例

**依赖** 可复现的 macOS arm64 Engine/Editor 构建、原 FantasyKingdom 工程及带 GUID 的源资源，或 [仓库内第三人称示例](../GameSprout/Examples/ThirdPerson/README.md) 用于初期试验。

1. 从当前 Build Settings 导出两个可区分的游戏版本，第二版只改一项可识别的资源或设置。保留两份不可变产物和对应 Player 清单。
2. 生成发行清单样例，记录游戏 ID、平台、架构、引擎构建 ID、包大小、摘要和签名。试验可使用测试信任根。验证系统签名和清单真实性时分别记录结果。
3. 在独立安装目录跑通读取、验证、安装、启动。通过替换数据验证破损、错误架构、错误引擎对应关系和过期清单。
4. 把实际独立 Player 的运行写成可重复的验证。校验包加载 GameLogic、进入启动场景、W / 右键作用于游戏。首帧对应渲染冒烟，交互成功才纳入可玩验收。
5. 模拟新版安装失败，确认旧版仍能启动，已运行版本不会中途被替换。将存档放在安装目录外，执行可兼容回滚和一次需阻止的存档迁移。

**验收** 一份可读清单和可复跑命令，一份实际安装运行成功记录，以及校验拒绝、输入回归、安装恢复三类证据。记录遗留问题与公开接口建议，保留原项目和原测试包。

## 阶段 1 · 私有 macOS 发行

**依赖** 本地样例跑通，准备正式分发签名身份、干净 macOS 环境和小范围邀请账号。

* 发行服务记录公司官方引擎、开发者游戏版本、目标变体和测试渠道。实现权限、幂等上传、暂存校验、审批、审计及每目标状态。首批创作者可上传本地构建的完整包。
* Editor 可提交候选包、恢复或取消上传、查询发行状态和错误。从另一台开发机登录，同样可看本团队的现有发布记录。
* Launcher 读目录、下载、验签、安装和启动完整签名包。失败的安装可恢复，存档按游戏与用户保存。
* 使用 FantasyKingdom 和一至两款独立项目验证。额外项目应覆盖较小的资源负载或不同玩法，确认流程可复用。
* 验证正式签名、公证，以及正常用户从可信入口获取并启动新包。在至少一次有已知回归的测试版本上验证暂停范围、回到旧版和存档处理。

**验收** 一台机器发布，另一台干净的 Mac 可发现、安装并进入游戏。新版可更新，回退后的存档行为有记录。未批准的包不可走公开下载路径。无权限的发布者无法修改他人游戏。

## 阶段 2 · 质量、成本和可恢复性

**依赖** 私有发行已有真实操作数据，能够取得有授权的设备样本并复现失败。

* 记录构建来源、设备检查、阶段时间、输入和渲染健康、安装及启动错误。按构建保存符号与获准的诊断。Editor 可从发行版本跳回相关资源或诊断上下文。
* 支持灰度发行和运营暂停。按版本、目标或地区处置异常，验证恢复时旧版本和已撤销版本的可用性符合预期。
* 实施请求前边缘鉴权和字节预算，冷缓存与热缓存均验权。并发重试受预算约束。构建、上传、存储和日志另有对应控制。
* 用 FantasyKingdom 小范围改动验证差分。复用未变字节，组装后系统签名通过。测试断点续传、磁盘不足、并发更新与运行、服务暂时不可达。
* 演练恶意候选、签名凭据泄露、坏版本、备份恢复和重试风暴。重要原生发行路径在干净环境复验。

**验收** [运营与质量](04-operations-and-quality.md) 和 [分发与安装](03-delivery-and-installation.md) 的重点场景都有执行证据、环境和结果。用私有试点数据确定具体 SLO、流量成本门槛与灰度样本。文档中的示例数值供设计验证。

## 阶段 3 · 第二目标、商店和公开发行

* 第二个桌面目标在 Windows 与 Linux 之间按市场意图、工具链和设备资源决定。Windows 先补完整导出器。Linux 要量测运行库、驱动、包格式和更新行为。每个目标独立验证签名、安装与实际输入。
* 移动先为游戏和官方引擎补独立应用交付流程。代码组合、签名、商店上架、启动与更新按渠道评估。iOS、Android 和 HarmonyOS 的实际成功证据分别记录。
* 公开接入前完成组织身份、角色授权、签名恢复演练、原生执行权限、上传/构建隔离、举报下架、支持与隐私处理，明确由谁操作暂停和恢复。
* 有实际安装与更新数据后再评估跨游戏共享引擎、分阶段资源加载和多 CDN。交易、云存档、联机服务按真实需求进入独立阶段。

**公开发行门槛** 能确认每个目标适用的渠道，真实版本可暂停与回退，安全和投诉有处理路径，运营能追溯资源和费用归属。未达门槛的目标维持私有测试状态。

## 测试矩阵及度量

| 维度 | 最小可复查记录 | 后续扩展 |
| --- | --- | --- |
| 系统与硬件 | 平台、CPU、系统版本、GPU/驱动、分发方式 | 按活跃玩家设备分布分配测试机，兼顾低空间、低带宽和旧系统 |
| 构建与依赖 | 代码提交、目标、引擎构建、GameLogic ABI、摘要、签名状态 | 符号、资源变更图、工具链及灰度的产物一致性 |
| 安装与更新 | 首装、续传、拒绝损坏、运行版本保护、回滚存档结果 | 版本跨度、多游戏并行、离线授权、区域故障 |
| 游戏运行 | 启动场景、首次可交互、实际输入、退出结果 | 设备性能、包内 Shader、场景转换和重复启动 |
| 风险与运营 | 权限隔离、撤销、预算拒绝、失败来源与动作审计 | 双人审批、密钥轮换、备用区域与灾难恢复 |

保持分母一致。发布耗时以提交到一个**指定平台**玩家可装为准。首次可玩率基于可比较的首次启动尝试。安装成本计入成功安装所需下载、失败重试及按游戏分摊的构建、存储、监控和支持。对比使用相同地区、带宽、机型组及采样时间。

改动合并前核对真实入口、版本选择、权限、故障恢复、数据影响和未覆盖环境。测试写日期、提交、发行 ID、运行机型、执行命令、输出及局限。下一条任务同时更新 [交接页](06-workspace-and-handoff.md)，关键变化追加到 [决策记录](DECISIONS.md)。
