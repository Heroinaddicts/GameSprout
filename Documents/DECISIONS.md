## ADR-001 · 公司发布引擎，开发者发布游戏

公司控制官方引擎、SDK、工具链及官方签名。开发者提交本团队游戏资源、GameLogic 和发布说明，锁定已发布的引擎构建。发布者维护授权游戏及渠道，官方引擎和平台信任策略由公司管理。

用户已明确两种发布职责。公司引擎更新与游戏迭代有各自节奏。安全处置可从引擎构建反查受影响游戏，创作者可对不同游戏选择不同版本。任何扩大权限的设计都须重新检视两个角色的边界。

## ADR-002 · 游戏绑定按目标交付的官方引擎

实际运行组合由游戏版本、平台、架构、引擎构建 ID、GameLogic ABI 和目标产物摘要描述。`1.2.30` 是文档示例。引擎构建包含 Player、Runtime、GRHI、Foundation 所用能力、SDL 和实际平台依赖，动态或静态划分随构建。

原生 C++ 兼容性依赖 SDK、编译器和运行库。Shader 和预处理资源有平台与数据格式要求。当前按已验证组合匹配。若以后引入稳定兼容层或 ABI 兼容的补丁替换，先记录跨版本学习成本、真实测试、构建身份和更新/回滚策略。 [现有 ABI 定义](../GameSprout/GameSproutRuntime/Api/RuntimeScriptApi.h)

## ADR-003 · 独立 Launcher 和 Player

Launcher 管目录、授权、安装、更新及启动。游戏在独立 Player 进程执行，Runtime 保持独立于 Editor 和 Qt。按已确认的平台策略使用 Metal（macOS/iOS）、D3D12（Windows）或 Vulkan（Linux/Android，鸿蒙当前走 Vulkan 实现分支）。进程隔离覆盖生命周期和崩溃，文件和网络权限明确交由操作系统与发行策略配置。

移动原生代码按对应渠道交付，统一目录记录渠道状态。若以后先做单一移动 Hub 内即玩，需另行决定 Web 或串流方案及兼容、延迟和部署成本。 [图形后端实现](../GameSprout/GRHI/GRHI/DeviceSDL.cpp) · [平台矩阵](01-platform-architecture.md)

## ADR-004 · 首版桌面完整签名包

基于已发布的 EngineBuild 与 GameRelease 组装完整的签名 Player。Launcher 下载、校验、安装及启动完整产物。保留精确引擎身份，为后续共享留出选择。正式 macOS 发行按 Developer ID 和公证路径验证。

实际 FantasyKingdom macOS 测试包中，Player 和引擎相关文件约 19.8 MiB，游戏资源约 1784 MiB，均为未压缩文件大小。这个单样本支持先投入安装、兼容、签名及资源差分。等多款游戏的实际缓存命中、传输收益、签名可行性和维护成本齐备，再评估共享引擎。

## ADR-005 · 不可变版本、目标和渠道

官方构建及游戏目标产物发布后以摘要辨识，渠道修订引用获批准的目标。可对单个目标重试、暂停、灰度或撤回。正常回退产生新的经授权渠道修订，指向仍可交付的旧产物。客户端验证渠道的新鲜度，再校验旧产物身份。

该设计允许各目标独立发布。恢复旧版时检查存档格式和服务端协议。若未来存在一款游戏须各目标同时可见的业务要求，通过具体渠道策略表达并验证。

## ADR-006 · 发布信任、平台签名与权限

上传走短效、限范围权限和隔离暂存区。来源、批准及签名与产物摘要绑定。签名密钥按角色隔离。产物在调用系统安装器或装载 GameLogic 前完成校验。团队账号授权、仓库发布签名、目标系统信任有独立职责。第三方代码执行采用平台允许的权限方案，运营支持按游戏或构建撤销。

私有试点先接收本地构建产物。开放范围扩大前，验证构建隔离、签名管理、发布者权限、事故响应、密钥轮换与恢复。平台签名主体按实际渠道确定。 [发行与信任](02-release-and-trust.md)

## ADR-007 · 请求前预算与可恢复安装

发行下载在 CDN 边缘前置验权，在发送已知尺寸数据前占用预算，私有源站只接受授权回源。账单用于对账，实时链路控制止损。新版本在暂存目录校验，具备恢复记录后再激活。已运行版本和验证过的分块按生命周期保留。存档与安装版本独立。

方案针对重复下载、并发重试、盘不足、中断恢复及坏版本。供应商限额、日志延迟、分块与账单条款决定实现。 [分发与安装](03-delivery-and-installation.md)

## ADR-008 · 生产问题驱动真包回归

将候选包上的设备检查、运行指标和生产故障关联到游戏版本、引擎、设备和资源身份。用 FantasyKingdom 的打包输入故障做首个回归夹具，其他独立项目验证可复用。处置事故时记录受影响范围与证据，修复后持续跑同一用例。诊断使用最小必要信息，并遵循游戏与团队访问权限。

发布耗时、坏版本恢复时间和每次成功安装总成本用作试点价值指标。发现、留存、支付和售后分别衡量。 [运营与质量](04-operations-and-quality.md)

## ADR-009 · 待验证的选择

| 议题 | 决策需要的证据 |
| --- | --- |
| 后端技术栈 | 按账号授权、版本事务、幂等上传、队列、审计、部署和值守评估。仓库的 `Go/` 可作为候选，先验证其适用边界 |
| Launcher 是否复用现有 Hub | 当前 Hub 是项目启动器。按独立产品生命周期、跨端 UI、系统安装、账号隔离及可维护性验证 |
| 第二个桌面目标及移动范围 | Windows 尚缺导出器，Linux 已有导出路径。按设备、市场和商店签名能力决策 |
| 本地上传与云构建 | 首批可由本地构建。云端执行前验证 SDK、许可、隔离、来源记录和成本 |
| CDN 与对象存储供应商 | 地区覆盖、出站费率、鉴权顺序、实测限额、日志和费用边界 |
| 公开发行、付费和联机 | 真实试点需求、权限与审核主体、权益退款、客服、协议和隐私边界 |
