# GameSprout Game Launch Platform

本目录维护 GameSprout 游戏发行与启动平台的设计、工程现状、验收标准和交接记录。开发者在 Editor 提交游戏发行，玩家在独立 Launcher 里发现、安装、更新和启动游戏。GameSprout 公司发布官方引擎，开发者独立发布游戏版本，游戏清单绑定已通过验证的引擎构建。

**基线日期** 2026-11-23。**引擎代码基线** `d8053d0`。**平台状态** 设计完成首轮整理，已有 Editor、独立 Player、目标平台导出和资源依赖收集。尚未实现面向玩家的 Launcher 安装器、发行服务及线上发布流水线。样例版本号 `1.2.30` 只用于解释版本绑定。

## 换电脑后从这里继续

1. 查看 [换机与交接](06-workspace-and-handoff.md) 的「当前接力点」。确认 Git 分支、工具链、SDL 定制 SDK、测试项目和上一轮已验收的结果。
2. 在 [路线图与验收](05-roadmap-and-acceptance.md) 找到当前第一条待办。每次只拿一个可验证的切片，完成后写实际测试证据。
3. 涉及职责、签名、格式、兼容策略或发布渠道的变更，先读 [决策记录](DECISIONS.md)。新的决定追加条目，并同步更新受影响的设计页和验收用例。
4. 阅读仓库根目录的 [AGENTS.md](../AGENTS.md)。服务、模块和界面改动沿用当前的边界、事件和 Git 提交约定。

## 维护方式

稳定的接口、状态、术语在对应设计页维护。项目进度集中在路线图和交接页。引用仓库文件用相对路径，日期使用 `YYYY-MM-DD`。开发机绝对路径、签名私钥、商业资产、已打包游戏和运行日志通过各自受控位置管理，文档只记录可移植的配置入口、提交、摘要或能找到证据的引用。

每次合并时更新相关文档和接力点。写清「完成、实际验证、下一步、阻塞」四项，测试未执行就写待验，历史数据带环境和采样范围。已采纳决策发生变化时，新增一条记录并指向它替代的编号，方便新电脑沿 Git 历史还原上下文。
